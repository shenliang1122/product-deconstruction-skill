# 产品类型路由

只读取与当前产品行为匹配的章节。选择一个主要类型，必要时选择一个次要类型。

## 分类方法

根据产品的核心闭环判断类型：

- 用户提供了什么？
- 系统决定或执行了什么？
- 最终沉淀的结果是什么？
- 产品价值主要积累在哪里：资产、已完成任务、关系/记忆、工作流定义、内容还是交易？
- 哪种失败最容易破坏用户信任？

输出分类结论、证据编号、考虑过的其他类型和置信度。

## AIGC 创作工具

核心闭环：创作需求/素材 → 规划/配置 → 生成 → 审核/编辑 → 资产/导出。

分析重点：

- 原始需求、剧本、风格、参考资料、画面比例、语言、时长；
- 分阶段资产：角色、场景、道具、分镜、图片、视频、音频；
- Prompt 生成以及用户是否可以编辑 Prompt；
- 生成模型、版本、分辨率、时长和参考能力；
- 先生成样例还是批量生成，以及成本与延迟权衡；
- 资产血缘、稳定引用、版本、一致性及下游失效机制；
- 质量检查：风格、角色一致性、时序连续性、对白/音频同步；
- 部分成功、重新生成、重复扣费和最终合成完整性。

完成不能只依赖 Agent 的口头声明。只有请求的资产真实存在、通过验证、已存储或被引用，并且能够预览或导出，才算完成。

## 通用执行 Agent

核心闭环：用户意图 → 计划 → 工具动作 → 外部或系统状态变化 → 验证/恢复。

分析重点：

- 任务范围、权限、副作用边界和用户授权；
- 规划、执行和观察之间的区别；
- 工具选择、参数构造、执行前确认和结果验证；
- 长任务、异步状态、暂停/恢复/取消、重试和幂等；
- 外部协作与不可逆操作；
- 权威任务状态、审计记录和部分完成后的恢复机制；
- 跨步骤保留的记忆或上下文；
- 是否根据真实世界状态而不是文字回复判断完成。

对于这类产品，严谨的状态机和工具契约通常比创作资产分类更重要。

## 对话陪伴产品

核心闭环：对话 → 情绪/人格回应 → 记忆与关系连续性 → 用户再次使用。

分析重点：

- 人格、语气、关系定位、用户期待和情绪状态；
- 短期对话上下文与长期记忆；
- 记忆的创建、纠正、删除、可见性和用户授权；
- 安全边界、危机处理、依赖风险、年龄和身份问题；
- 主动消息、提醒、连续使用记录、通知和留存机制；
- 可见的语音、虚拟形象和多模态行为；
- 模型一致性、拒绝方式、隐私和虚假记忆；
- 用户对人格、关系边界和数据保留的控制。

如果产品核心价值是关系体验，不要强行套用复杂工具编排。最高风险通常是信任、隐私或情绪伤害，而不是任务执行失败。

## Agent/工作流搭建产品

核心闭环：定义 Agent/工作流 → 配置工具、模型和数据 → 测试 → 观察 → 版本化/部署。

分析重点：

- 节点/步骤模型、触发器、条件、变量、工具契约和运行环境；
- Prompt/指令编辑与模型选择；
- 密钥和权限，但不得读取敏感值；
- 测试模式、运行轨迹、调试、重放、评估和部署版本；
- 工作流状态、分支、循环、并发、重试和人工确认节点；
- 可复用模板、组件和环境晋级；
- 运行历史、成本、延迟、故障定位和回滚。

## 通用 SaaS/工作台

核心闭环：创建、读取、修改和组织领域记录，并与他人协作。

分析重点：

- 信息架构、导航、搜索/筛选、记录生命周期和批量操作；
- 角色、权限、协作、评论、通知、历史、导入/导出；
- 领域规则和数据校验；
- API 与外部集成边界；
- 数据模型、审计能力、性能、离线和实时行为。

如果没有 AI 行为证据，模型层可以很简短，甚至标记为不适用。

## 内容/社区产品

核心闭环：消费/创作内容 → 分发/推荐 → 互动 → 留存/变现。

分析重点：

- 内容创作和审核；
- 信息流/导航、推荐证据、排序信号和探索机制；
- 身份、社交关系、互动、通知和创作者激励；
- 内容生命周期、安全、版权和隐私；
- 商业化与信任安全之间的权衡；
- 实验机制和反馈信号。

## 交易/市场平台

核心闭环：发现 → 比较 → 确认交易 → 履约 → 售后/争议。

分析重点：

- 商品目录、搜索/筛选、方案比较、库存、价格、费用和信任信号；
- 结算/提交确认和支付边界；
- 库存/预订、履约、状态、取消、退款和争议；
- 买家、卖家和合作方的角色与权限；
- 欺诈、安全、合规和审计能力；
- 资金状态和不可逆操作验证。

不能为了收集证据而真实执行交易。

## 多类型产品

当产品同时具有多种特征时，选择一个主要闭环，只继承次要类型中真正相关的检查项。例如：

- AIGC 工具 + 工作流搭建：同时关注资产血缘和节点/运行/版本；
- 执行 Agent + 对话陪伴：同时关注工具权限和记忆/情绪安全；
- 通用 SaaS + 内嵌 AI：仍以核心记录生命周期为主，模型分析只覆盖有证据的 AI 功能。

不要把所有清单简单合并。需要说明哪些方面被有意降低优先级。
