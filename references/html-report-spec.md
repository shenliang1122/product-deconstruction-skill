# 独立 HTML 报告规范

生成最终交付物前必须读取本参考资料。

## 文件与安全

- 在用户控制的持久目录中生成一个独立、UTF-8 编码的 HTML 文件。
- 文件名应由通用分析目标简洁生成，不能包含秘密或账号凭证。
- 不得嵌入 Cookie、Token、密码、私有身份信息、浏览器存储或敏感日志。
- 如果报告与本地证据位于同一目录，优先使用相对路径链接证据；只有确有需要时才使用绝对本地路径。
- 除了渲染所需的稳定库，避免使用远程资源。图表需要 Mermaid 时，可以使用 jsDelivr 上的 Mermaid。
- 必须包含打印样式和窄屏样式。

## 必须展示的证据语言

提供可见图例：

- `【页面/代码事实】`
- `【合理推断】`
- `【建议设计】`
- `【尚未确认】`
- 可选：`【证据冲突】`

每一行重要表格、每个重要图节点/连线和每项架构结论，都必须带有标签或证据编号。

## 默认报告顺序

1. 标题和一句话架构摘要
2. 分析范围和产品类型
3. 证据就绪度、来源清单、缺口与冲突
4. 执行摘要
5. 用户层
6. 技术层
7. 模型层
8. 数据层
9. 端到端跨层流程
10. 当前架构（As-Is）
11. 建议架构（To-Be）
12. 风险与失败模式
13. 证据追溯矩阵
14. 尚未解决的问题和下一步需要收集的证据

如果用户只要求用户旅程或单个 Agent 契约等有限交付物，可以调整顺序，但相关的四层分析仍要保留。

## 证据表

每行证据应包含：

| 编号 | 顺序/时间 | 来源 | 页面原文/控件/代码 | 状态/资产 | 支持的结论 | 等级 |
|---|---|---|---|---|---|---|

冲突记录必须包含所有相互矛盾的信号，并避免断言不可见的底层原因。

## 图表

使用能够解决问题的最小图表：

- 用户行为使用旅程图或决策流程；
- 用户 → 工作流/Agent → 工具/模型 → 数据/资产，使用时序图；
- 长任务或需要审批的流程使用状态图；
- 分层架构使用流程图；
- 数据关系使用 ER 图或生产者—消费者关系图。

图表规则：

- 所有判断节点和分支必须写明条件；
- 区分已观察、合理推断和建议设计的组件；
- 重要节点必须包含证据编号，或由对应证据表支撑；
- 证据支持时，应展示正常、修改和失败/中断路径；
- 不得把不可见后端画成已确认事实。

## 视觉设计

- 使用高对比度文字、响应式表格，并为长报告提供吸顶导航。
- 装饰性视觉不能影响证据阅读。
- 为证据文件提供可点击链接。
- 对长 Prompt 或契约使用 `<pre>`，必要时提供复制按钮。
- 对证据缺口和状态冲突使用醒目的警示样式。

## 校验

交付前：

- 检查所有必需章节是否存在；
- 使用 `tidy` 等可用工具验证 HTML；
- 检查 Mermaid 代码块是否闭合，并排除明显语法错误；
- 检查本地证据链接对应的文件是否存在；
- 搜索未替换的占位内容，例如 `TODO`、`TBD` 或模板占位符；
- 确认建议方案没有被写成当前事实；
- 环境允许时，打开并渲染 HTML 文件进行检查。

如果浏览器安全策略阻止本地文件导航，不得绕过限制。应进行静态验证，说明无法渲染的原因，并照常交付文件。
